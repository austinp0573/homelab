# standard-notes env

`render.sh` substitutes listed vars into compose; server also gets the full `.env` via `env_file`. fill DB passwords + auth secrets before up.

| name (key) | default value | purpose + notes |
| --- | --- | --- |
| `STANDARDNOTES_CONTAINER_NAME` | `standardnotes` | App container name after render; scripts and proxies should match. Changing it without re-render leaves stale compose. Collision if another stack reused the name. Keep stable once clients bookmark the host publish. |
| `STANDARDNOTES_HOST_PORT_0` | `3000` | Host publish → container `3000` (main HTTP). Binding `0.0.0.0` exposes the API without another gate — prefer loopback + reverse proxy. Changing this breaks bookmarks and HAProxy backends until updated. Must stay unique on the host. |
| `STANDARDNOTES_HOST_PORT_1` | `3125` | Host left side is `3125`, but the container right side is **`3104`** — not 3125. People copy the host port into the container mapping and break the second listener. Used for sync/websocket-style traffic depending on server build. Document both sides whenever you change either. |
| `STANDARDNOTES_NETWORK_NAME` | `standardnotes-net` | Dedicated compose network for app/db/redis/localstack. Renaming after first up orphans the old network and may leave containers on the wrong net. Keep external:false unless you intentionally share with another stack. DNS names (`db`, `cache`) only resolve on this net. |
| `LOCALSTACK_CONTAINER_NAME` | `standardnotes-localstack` | SNS/SQS stub so the server can “publish” without AWS. Not production AWS — data is ephemeral/lab-only. If Localstack is down, some async paths fail while HTTP still looks healthy. Do not point real AWS creds at this container by accident. |
| `DB_CONTAINER_NAME` | `standardnotes-db` | MySQL container name post-render. Used for `nerdctl exec` and volume mental models. Renaming requires re-render + recreate. Keep in sync with any backup scripts that target this name. |
| `DB_HOST` | `db` | Hostname the app uses via `env_file`; must match the compose service name, not the container_name. Using `localhost` from the app container is wrong. Changing service name without updating `DB_HOST` = connection refused. Internal-only — never publish MySQL for convenience. |
| `DB_PORT` | `3306` | MySQL listen port inside the network. App and official image expect 3306 unless you customized both sides. Publishing this to the host is a common mistake — leave it internal. Mismatch with `DB_HOST:DB_PORT` in app env breaks boot. |
| `DB_USERNAME` | `std_notes_user` | Becomes `MYSQL_USER` on the db container and the app’s DB user. Changing after first init does nothing useful — the volume already has the old user. Keep identical across app + MySQL env. Not a secret by itself; pair with `DB_USER_PASSWD`. |
| `DB_ROOT_PASSWD` | `<secret>` | Maps to `MYSQL_ROOT_PASSWORD`. **Required** — empty root password fails modern MySQL images. Only needed for admin/bootstrap; app should use the app user. Rotate carefully: volume already initialized keeps old hash until you intervene. Never commit real value. |
| `DB_USER_PASSWD` | `<secret>` | Maps to `MYSQL_PASSWORD` for `DB_USERNAME`. **Required** before first up. Must stay in sync with whatever the app reads as its DB password. Changing after init without altering MySQL users breaks the app silently at query time. Treat as `<secret>`. |
| `DB_PASSWORD` | `<secret>` | Present in `.env.example` for the app `env_file` path; keep equal to `DB_USER_PASSWD`. Drift between these two is a classic “MySQL accepts login, app rejects” split-brain. Prefer one source of truth and copy deliberately. Mark both `<secret>` in real deploys. |
| `DB_DATABASE` | `standard_notes_db` | Database/schema name created on first MySQL boot. Renaming later needs dump/restore — empty new name looks like a fresh install. App and MySQL must agree. Appears in connection strings; typo = unknown database. |
| `DB_TYPE` | `mysql` | Tells the Standard Notes server which driver to use. Wrong value with a MySQL backend = startup driver errors. Do not set `sqlite`/`postgres` unless the stack actually provides that. Leave as `mysql` for this template. |
| `REDIS_CONTAINER_NAME` | `standardnotes-redis` | Cache/queue Redis container name. Useful for logs and `redis-cli` via exec. Renaming needs re-render. If Redis is down, sessions/cache paths degrade even when MySQL is fine. |
| `REDIS_PORT` | `6379` | In-network Redis port; app connects here via `REDIS_HOST`. Do not publish to the host unless debugging. Changing requires matching app env + redis config. Default is correct for `redis:6` images. |
| `REDIS_HOST` | `cache` | Compose service DNS name for Redis — not `redis` and not `localhost`. Wrong host is a frequent copy-paste from other stacks. Only resolves on `STANDARDNOTES_NETWORK_NAME`. Keep aligned with the service key in the tmpl. |
| `CACHE_TYPE` | `redis` | Selects Redis as the cache backend for the server. Setting something else without providing that backend breaks cache init. Pair with healthy Redis; do not leave as redis if you removed the cache service. Restart app after changes. |
| `AUTH_JWT_SECRET` | `<secret>` | JWT signing material — generate with `openssl rand -hex 32`. Rotating logs everyone out and invalidates outstanding tokens. Empty/weak values are a security bug on any exposed deploy. Keep out of git; required before real use. |
| `AUTH_SERVER_ENCRYPTION_SERVER_KEY` | `<secret>` | Server-side encryption key for auth payloads; same generation pattern as JWT. Rotating can strand encrypted server-side material — treat like a break-glass change. Must be stable across restarts or auth breaks oddly. Never reuse across unrelated environments. |
| `VALET_TOKEN_SECRET` | `<secret>` | Valet/token secret for file/auth flows; generate like the others (`openssl rand -hex 32`). Mismatch or empty secret causes token validation failures that look like client bugs. Rotate only with a planned re-login window. Store as `<secret>`. |
| localstack | `SERVICES=sns,sqs`, `HOSTNAME_EXTERNAL=localstack` | Hardcoded in tmpl — enables SNS+SQS only, enough for SN’s stub needs. `HOSTNAME_EXTERNAL` must match how the app addresses Localstack on the compose net. Expanding SERVICES increases RAM for no benefit here. Do not confuse with real AWS endpoints. |
| images | `standardnotes/server`, `mysql:8`, `redis:6.0-alpine`, `localstack/localstack:3.0` | Pins vary by tmpl; pin the server tag for prod so sync protocol stays predictable. MySQL 8 major jumps need dump testing. Redis 6 alpine is small and enough for this role. Bump Localstack only when the stub API you need changes. |
| volumes | `./logs`, `./uploads`, `./data/*` | Persist MySQL/redis/import artifacts on the host binds listed in tmpl. Deleting `./data` is a full reset. `uploads`/`logs` grow — include in backup or rotate. Permissions must allow the container users or boot fails with EACCES. |

re-run `./render.sh` after `.env` changes that affect compose substitution.
