# flatnotes env

`render.sh` runs `envsubst` over `compose.yml.tmpl` → `compose.yml`. all of the knobs below must be set in `.env` before render/up. skipping render and hand-editing `compose.yml` is how secrets and ports drift from the template you think you are running.

## .env

| name (key) | default value | purpose + notes |
| --- | --- | --- |
| `FLATNOTES_USER` | *(required)* | becomes `FLATNOTES_USERNAME` inside the container after render. this is the login identity for `FLATNOTES_AUTH_TYPE=password`. it has no useful default — render/up should fail closed if you leave it empty. common mistake is setting the username only in a running container env and losing it on the next `render.sh`. operational gotcha: changing the username does not migrate anything; it just changes who can log in next to the password and secret key. |
| `FLATNOTES_PASSWD` | `<secret>` | becomes `FLATNOTES_PASSWORD` in the rendered compose. ends up in `compose.yml` on disk after envsubst — treat that rendered file as sensitive if gitignore is not covering it. it interacts with `FLATNOTES_USER` as the password-auth pair. common mistake is putting the real password in a tracked `.env.example` or committing rendered `compose.yml`. operational gotcha: rotate by editing `.env`, re-render, recreate; old compose files in backup tarballs still contain the previous password. |
| `FLATNOTES_SECRET_KEY` | `<secret>` | session signing key for cookies/tokens. generate with `openssl rand -hex 32` (or equivalent) and keep it stable across recreates. rotating it immediately invalidates existing sessions and logs everyone out. it is independent of the password but equally secretful in the rendered compose. common mistake is regenerating it on every deploy "for security" and wondering why browsers keep bouncing to login. operational gotcha: back this up with the data volumes if you care about session continuity after a host rebuild; losing only the notes data is recoverable from backup, losing the key without noticing just looks like auth flapping. |
| `FLATNOTES_HOST_PORT` | *(required)* | host port mapped to container `8080`. required because the template does not pick a cute default for you. it interacts with whatever reverse proxy or Tailscale serve path points at flatnotes. common mistake is assuming container 8080 is published automatically without setting this before render. operational gotcha: port conflicts fail at create time; change `.env`, re-render, and recreate rather than editing only the old compose port line. |

## compose hardcodes (tmpl)

| name (key) | default value | purpose + notes |
| --- | --- | --- |
| image | `dullage/flatnotes:latest` | image reference hardcoded in the template. pin a digest or tag if upgrades matter on this host. `:latest` will move under you on recreate when the remote tag floats. common mistake is blaming `.env` for an app regression that was really an unpinned pull. operational gotcha: after pinning, record the working tag next to the data backup notes so restore includes the matching app version. |
| `PUID` / `PGID` | `1000` / `1000` | numeric user/group the app uses for files in the mounted data/index dirs. must match ownership on `./data` and `./index` on the host. they interact with bind-mount permissions — wrong ids mean notes fail to save or the index cannot be written. common mistake is running as root on the host to "fix permissions" and creating root-owned files the container can no longer update. operational gotcha: after restore from backup, `chown -R 1000:1000` (or your chosen PUID/PGID) before up. |
| `FLATNOTES_AUTH_TYPE` | `password` | only auth mode wired in this template. password auth uses the username/password/secret key trio from `.env`. there is no OIDC/SSO wiring here unless you extend the template yourself. common mistake is setting a different auth type in the UI or docs and expecting the tmpl to follow. operational gotcha: if you need SSO, do it at the reverse proxy or fork the template — do not assume an env toggle exists. |
| volumes | `./data`, `./index` → `/.flatnotes` | notes content and search index bind mounts into the container path Flatnotes expects. back up `data/` as the source of truth; index can usually be rebuilt but restoring both is faster. they interact with PUID/PGID ownership on the host paths. common mistake is backing up only compose/env and not `data/`, then recovering an empty notes app. operational gotcha: do not delete `index/` as casual cleanup while the app is running; stop first if you intend to force a rebuild. |
