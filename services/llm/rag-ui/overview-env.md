# rag-ui env

AnythingLLM UI against llama.cpp. optional vs Open WebUI RAG — don't dual-run both casually. start llama-cpp first.

| name (key) | default value | purpose + notes |
| --- | --- | --- |
| `COMPOSE_PROJECT_NAME` | `llm-rag-ui` | Compose project identity for the AnythingLLM stack. Keep it distinct from `open-webui` and `llm-rag-headless` so volumes and containers never collide. Renaming after first up orphans the named storage volume under the old project. I use this name in stop/start scripts when freeing resources without touching llama itself. |
| `CONTAINER_NAME` | `llm-anythingllm` | Stable container name for logs and `nerdctl exec`. Not the DNS name clients on the LAN use — publish is loopback. If you rename it, update any host scripts that assume this string. Avoid running a second AnythingLLM with a different name against the same docs dir unless you like lock fights. |
| `RESTART_POLICY` | `unless-stopped` | Survives reboot until you stop it on purpose. Fine for a lab UI you actually use; wasteful if you only need it occasionally and llama is the scarce resource. Stopping this does not free the GPU — llama-cpp still owns VRAM. Use stop when you are switching to Open WebUI as the only RAG front-end. |
| `LLM_NETWORK` | `llm-backend` | Must be the same external network llama-cpp joined. That is how `GENERIC_OPEN_AI_BASE_PATH` resolves `llama-cpp` without hairpinning through the host. If the network is missing, compose fails at create time — run the ensure script first. Do not invent a private network for AnythingLLM alone or you will be tempted to point at `172.17.0.1`. |
| `HOST_BIND` | `127.0.0.1` | UI listen bind on the host. Loopback means browser via SSH tunnel or local HAProxy, not open LAN. AnythingLLM has its own auth story; still do not publish it wide by default. Changing to `0.0.0.0` is a conscious exposure decision, not a convenience default. |
| `HOST_PORT` | `3001` | Host port → container `:3001`. Picked to stay off Open WebUI's `3000`. Collision with another lab UI is a silent bind failure depending on runtime. Bookmark the port; the container port is not what you type in the browser when published this way. |
| `ANYTHINGLLM_IMAGE` | `mintplexlabs/anythingllm:1.11.1` | Pinned AnythingLLM release. Floating `latest` is how workspace DB migrations surprise you on recreate. Bump deliberately after reading release notes for embed/provider changes. Image upgrades can rewrite on-disk workspace state — snapshot the volume first if you care about collections. |
| `DOCS_DIR` | `/opt/llm/rag/docs` | Host corpus mounted read-only at `/docs`. Same tree rag-headless scripts use; keep one source of truth for files. Read-only prevents the UI from mutating the shared corpus in place. Empty dir means empty workspace until you upload or mount real documents. |
| `LLM_PROVIDER` | `generic-openai` | Tells AnythingLLM to use the generic OpenAI-compatible provider path. Other provider values expect cloud keys and different env shapes. Wrong provider with a local base path fails in the UI with opaque "provider error" toast. Leave this alone unless you are intentionally wiring a different backend. |
| `GENERIC_OPEN_AI_BASE_PATH` | `http://llama-cpp:8080/v1` | OpenAI-compat base URL including `/v1`. Prefer service DNS on `llm-backend`; compose may fall back to `http://172.17.0.1:8080/v1` if unset, which breaks when llama is not published or firewall drops docker bridge. Trailing slash and missing `/v1` are common footguns. llama must be up before AnythingLLM's first model probe. |
| `GENERIC_OPEN_AI_API_KEY` | `local` | Dummy bearer; llama.cpp does not authenticate. Some clients require a non-empty key, so `local` keeps them quiet. Putting a real secret here does nothing useful against llama and trains bad habits. If you later front llama with a real gateway, replace this and rotate assumptions. |
| `GENERIC_OPEN_AI_MODEL_PREF` | `local-model` | Model id string AnythingLLM sends in chat requests. llama.cpp often ignores or aliases this depending on build/flags — mismatch shows up as "model not found" or silent default. Align with whatever `/v1/models` returns after llama starts. Renaming for cosmetics without checking the server list wastes an afternoon. |
| `GENERIC_OPEN_AI_MODEL_TOKEN_LIMIT` | `8192` | Client-side context budget AnythingLLM assumes for the model. Should match llama `CTX_SIZE` or you will over-send and get truncations or errors. RAG retrieval plus chat history counts against this; leave headroom. Raising it here without raising llama ctx is wishful thinking. |
| `STORAGE_DIR` | `/app/server/storage` | In-container path for AnythingLLM's named volume (workspaces, vectors it owns, settings). This is not `DOCS_DIR` — wipe storage and you lose UI state even if docs on disk remain. Back it up if the workspaces matter. Do not point this at the shared docs tree. |
| `SERVER_PORT` | `3001` | Port the Node server listens on inside the container; effectively hardcoded to match the publish mapping. Changing only `HOST_PORT` without this (if ever exposed) desyncs the map. I leave it at 3001 and only touch host publish. Treat as documentation of the container listen port. |
