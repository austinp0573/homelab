# grafana env

host-network Grafana. sibling stacks: `prometheus/` and `loki/` (their own overviews). admin user/password from env apply **only when `data/` is empty**.

## `.env` / compose

| name (key) | default value | purpose + notes |
| --- | --- | --- |
| `COMPOSE_PROJECT_NAME` | `grafana` | compose project name for this stack’s resources. keep it stable so sibling docs and scripts that assume `grafana` don’t drift. renaming mid-flight without cleaning old containers leaves ghosts. Keep the name stable so volumes, scripts, and muscle memory stay aligned. |
| `CONTAINER_NAME` | `grafana` | fixed name for logs and muscle memory. with `network_mode: host` the name still matters for `docker logs` / stop scripts. collisions fail start — don’t run two Grafanas with the same name. Proxy backends and smoke scripts often hardcode this string. |
| `RESTART_POLICY` | `unless-stopped` | comes back after reboot unless you stopped it on purpose. dashboards that vanish after a power cut defeat the point of observability. avoid `no` on anything you rely on overnight. Use an explicit stop for maintenance; otherwise expect it back after reboot. |
| `GRAFANA_IMAGE` | `grafana/grafana:11.6.3` | pin the image; majors move provisioning and plugin APIs. bump deliberately and smoke datasources + login. floating `latest` on a host-network service is how surprise upgrades hit production. Majors move provisioning and plugin APIs — smoke datasources after bumps. |
| `GF_SERVER_HTTP_ADDR` | `127.0.0.1` | listen address under host networking — loopback keeps it off the LAN. set `0.0.0.0` only if you intentionally bind all interfaces. wrong addr + host net is a common “can’t reach Grafana” after copy-paste from bridge tutorials. Operational detail matters here — verify against the running compose when unsure. |
| `GF_SERVER_HTTP_PORT` | `3000` | HTTP listen port on the host. conflict with another 3000 service fails bind; change and update ROOT_URL + proxy. HAProxy backends usually target this port on loopback. Update every proxy and smoke script that still points at the old listen. |
| `GF_SERVER_ROOT_URL` | `http://127.0.0.1:3000` | public URL Grafana uses for redirects, alert links, and some auth flows. set this to the HTTPS name users actually hit when HAProxy/Tinyauth is in front or cookies/redirects break. mismatch shows up as “login loops” and wrong alert URLs. Use the name clients actually type, not a container-local address. |
| `GF_SERVER_DOMAIN` | `localhost` | domain Grafana thinks it serves; keep aligned with how you access it. leftover `localhost` behind a real hostname is mostly cosmetic until cookies/auth care. update with ROOT_URL when exposing via a real name. Use the name clients actually type, not a container-local address. |
| `GF_SECURITY_ADMIN_USER` | `admin` | bootstrap admin username **only if `data/` is empty**. changing env later does nothing if sqlite/grafana.db already exists — change in UI or reset data. don’t rely on env as ongoing identity management. Operational detail matters here — verify against the running compose when unsure. |
| `GF_SECURITY_ADMIN_PASSWORD` | `changeme` / `<secret>` | same bootstrap-only rule as the user. `up.sh` warns if still `changeme` — heed it. after first start, change in the UI; rotating only in `.env` will confuse you when login still accepts the old password. Keep the real value out of git and shell history. |
| `GF_USERS_ALLOW_SIGN_UP` | `false` | disables open signup on the login page. leaving true on a reachable instance is asking for random accounts. keep false unless you have a deliberate invite workflow. Operational detail matters here — verify against the running compose when unsure. |
| `GF_AUTH_ANONYMOUS_ENABLED` | `false` | anonymous Viewer access off by default. enabling for “just dashboards” often overshares Explore and more than you meant. prefer Tinyauth/proxy auth if you need gated anonymous-looking access. Operational detail matters here — verify against the running compose when unsure. |
| `GF_INSTALL_PLUGINS` | *(empty)* | comma-separated plugin ids installed on start. typos fail plugin install and can delay ready; pin versions when the image supports it. empty is fine until you actually need a panel type. Operational detail matters here — verify against the running compose when unsure. |
| `DATA_DIR` | `./data` | host path → `/var/lib/grafana`. chown `472:472` if the container can’t write (permission denied on start). wiping this resets admin password env bootstrap and destroys dashboards — back it up. Wipe equals data loss unless you have a restore you have actually rehearsed. |
| `GF_PATHS_DATA` | `/var/lib/grafana` | compose-hardcoded data path inside the container. don’t change unless you also change the volume mount. wrong path = empty Grafana every restart. Edit the compose/config that owns it — .env alone will not move hardcoded values. |
| `GF_PATHS_PROVISIONING` | `/etc/grafana/provisioning` | compose-hardcoded provisioning root for datasources/dashboards. file provider dashboards live under here via mounts. editing only in the UI without `allowUiUpdates`/persistence expectations will confuse you. Edit the compose/config that owns it — .env alone will not move hardcoded values. |
| `GF_ANALYTICS_REPORTING_ENABLED` | `false` | hardcoded off — no phone-home usage stats. leave it; re-enabling is noise for a homelab. not related to your Loki/Prometheus telemetry. Edit the compose/config that owns it — .env alone will not move hardcoded values. |
| `GF_ANALYTICS_CHECK_FOR_UPDATES` | `false` | hardcoded off — no update check pings. you pin images yourself in compose. UI update banners are not how this stack upgrades. Edit the compose/config that owns it — .env alone will not move hardcoded values. |
| `user` | `472:472` | grafana uid/gid the process runs as; host `DATA_DIR` must be writable by this pair. root-owned `./data` from a previous mistaken run is a classic startup failure. fix with chown, not chmod 777. Fix bind-mount ownership instead of running the process as root. |
| `network_mode` | `host` | so datasources can hit `127.0.0.1` prometheus/loki on the host. bridge networking would break those URLs unless you rewrite to compose DNS or host.docker.internal. don’t mix mental models — this stack assumes host net. With host net, `HOST_BIND`/`GF_SERVER_HTTP_*` are the real exposure knobs; compose `ports:` publishing is irrelevant and easy to “fix” without effect. |

## provisioning

| name (key) | default value | purpose + notes |
| --- | --- | --- |
| Prometheus datasource `url` | `http://127.0.0.1:9090` | assumes Prometheus published on host loopback (sibling stack). wrong port/bind and Explore is empty with connection refused. if Prometheus isn’t host-published, change this URL to something Grafana (host net) can actually reach. Use the name clients actually type, not a container-local address. |
| Loki datasource `url` | `http://127.0.0.1:3100` | same pattern for Loki HTTP. Grafana does not talk to Alloy for queries — only Loki. if Loki bind isn’t loopback, adjust or you’ll only see metrics. Use the name clients actually type, not a container-local address. |
| dashboard provider `updateIntervalSeconds` | `30` | file provider poll interval for dashboard JSON on disk. lower is snappier deploys; higher is less FS churn. UI edits may fight file provider depending on `allowUiUpdates` and how you ship JSON. Tune from measured behavior, not the first number that felt safe. |
| `allowUiUpdates` | `true` | UI edits allowed on provisioned dashboards. true is convenient and also how “I fixed it in UI then provision overwrite lost it” happens — know your source of truth. set false if git/provisioning owns dashboards exclusively. Operational detail matters here — verify against the running compose when unsure. |
