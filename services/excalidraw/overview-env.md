# excalidraw env

UI + collab room (+ optional nginx basic-auth profile). no server-side drawing storage — browser / room only. if you need durable boards, that is an export/backup problem in the client, not a volume on this stack.

## .env / compose

| name (key) | default value | purpose + notes |
| --- | --- | --- |
| `COMPOSE_PROJECT_NAME` | `excalidraw` | compose project name for this UI/room/auth trio. keep it unique per host if you run more than one drawing stack. it prefixes networks and default resource names compose creates. common mistake is reusing the name across copies and fighting over containers. operational gotcha: rename only with a clean `down` of the old project so room state and networks do not orphan. |
| `EXCALIDRAW_CONTAINER_NAME` | `excalidraw` | container name for the static UI. browsers hit this (or the auth nginx in front) for the app shell. it interacts with the auth profile upstream name and with `UI_HOST_PORT` publishing. common mistake is renaming the UI container without updating `auth/nginx.conf` upstream references. operational gotcha: logs for "UI is blank" usually start here, not in the room container. |
| `ROOM_CONTAINER_NAME` | `excalidraw-room` | websocket collab server container name. this is the process behind `VITE_APP_WS_SERVER_URL`. it interacts with `ROOM_HOST_PORT` and CORS settings on the UI origin. common mistake is scaling or duplicating rooms while clients still point at one public URL. operational gotcha: room restarts drop live sessions; warn people before recreating it during a workshop. |
| `AUTH_CONTAINER_NAME` | `excalidraw-auth` | nginx basic-auth front container used only with profile `auth`. it is idle/absent when `ENABLE_BASIC_AUTH=n`. it interacts with `AUTH_HOST_PORT` and `secrets/htpasswd`. common mistake is enabling the profile without creating htpasswd, then watching nginx fail the config test. operational gotcha: point proxies at the auth port when enabled — leaving them on `UI_HOST_PORT` bypasses the gate entirely. |
| `RESTART_POLICY` | `unless-stopped` | shared restart policy for the services in this compose. brings UI/room back after reboot. it interacts with the auth profile — auth nginx should come back too or you get a mysterious dead entryport. common mistake is assuming room reconnect logic survives a host reboot without clients refreshing. operational gotcha: after reboot, verify both UI and room ports before declaring the stack healthy. |
| `EXCALIDRAW_IMAGE` | `excalidraw/excalidraw:latest` | UI image. `:latest` is fine for throwaway labs; pin for anything you need reproducible. it interacts with `VITE_APP_WS_SERVER_URL` baked/configured for the browser build behavior you rely on. common mistake is pinning UI but not room (or the reverse) and hitting protocol skew in collab. operational gotcha: bump UI and room together after reading release notes, then retest a two-browser session. |
| `ROOM_IMAGE` | `excalidraw/excalidraw-room:latest` | collab room image. pin in lockstep with the UI when stability matters. it listens on container port 80 internally regardless of host publish. common mistake is treating room like a normal HTTP app and putting basic-auth directly on it. operational gotcha: websocket proxies need long timeouts; short proxy idle timeouts look like "collab randomly dies." |
| `AUTH_IMAGE` | `nginx:1.27-alpine` | nginx image for the optional basic-auth profile only. unused when auth is off. pin if you care about nginx CVE churn on the gate. it only proxies to the UI service on the compose network. common mistake is upgrading nginx and breaking the mounted conf syntax without testing `nginx -t`. operational gotcha: auth image bumps still need a working `secrets/htpasswd` path or the container will not stay up. |
| `HOST_BIND` | `127.0.0.1` | bind address for published ports. keep loopback when Tailscale/Caddy/HAProxy is the real front door. it applies to UI, room, and auth publishes alike. common mistake is opening `0.0.0.0` because collab "didn't work," when the real bug was `VITE_APP_WS_SERVER_URL` or CORS. operational gotcha: wrong bind plus a public IP is how you accidentally expose an unauthenticated UI. |
| `UI_HOST_PORT` | `5000` | host port for the UI when basic auth is off. point reverse proxies here in the simple layout. it is ignored as the public entry when `ENABLE_BASIC_AUTH=y` — use `AUTH_HOST_PORT` then. common mistake is updating only one of UI vs auth ports in the proxy after toggling auth. operational gotcha: confirm which port is published with `ss`/`docker ps` after profile changes. |
| `ROOM_HOST_PORT` | `5001` | host publish for the collab room. the browser often never sees this port directly if a separate hostname terminates TLS in front. it must be proxied with websocket upgrade support and generous timeouts. common mistake is only proxying the UI hostname and forgetting a collab hostname entirely. operational gotcha: health checks that only hit `/` on the room can pass while websocket upgrades still fail through a misconfigured edge. |
| `AUTH_HOST_PORT` | `5002` | host port for the nginx auth front when `ENABLE_BASIC_AUTH=y`. public UI traffic should target this instead of `UI_HOST_PORT`. it interacts with `secrets/htpasswd` and the auth nginx upstream to `excalidraw:80`. common mistake is leaving bookmarks on `:5000` after enabling auth and thinking auth "does nothing." operational gotcha: the room port stays separate — do not fold room through this basic-auth nginx. |
| `VITE_APP_WS_SERVER_URL` | `https://collab.private.example.com` | public websocket base URL the browser will call for collab. must match DNS + TLS that actually reach the room service. it is not the docker-internal name; browsers are outside the compose network. common mistake is setting `http://room:80` or another compose DNS name the user's laptop cannot resolve. operational gotcha: change this together with `CORS_ORIGIN` and the reverse-proxy hostnames or collab breaks in non-obvious CORS/ws ways. |
| `CORS_ORIGIN` | `https://draw.private.example.com` | allowed origin for the room's CORS checks. must be exactly the UI origin users load, scheme included. it pairs tightly with `VITE_APP_WS_SERVER_URL` — UI origin and room URL are a matched set. common mistake is using a trailing-slash variant or http vs https mismatch. operational gotcha: after domain renames, update both env values and recreate; stale browser tabs will still show old errors until hard refresh. |
| `ENABLE_BASIC_AUTH` | `n` | `y` turns on `--profile auth` and expects `secrets/htpasswd` from `./scripts/htpasswd.sh`. `n` publishes the UI directly on `UI_HOST_PORT`. it interacts with which host port your reverse proxy should use. common mistake is setting `y` without generating htpasswd, or generating it but never switching the proxy to `AUTH_HOST_PORT`. operational gotcha: basic auth belongs on the UI only — never on the room websocket path. |
| room `PORT` | `80` | hardcoded listen port inside the room container. host mapping is `ROOM_HOST_PORT:80`. do not hunt for a room PORT env in `.env` — it is not wired that way here. common mistake is setting a host port and also trying to change an nonexistent room PORT env. operational gotcha: upstream targets on the compose network should use `excalidraw-room:80` (or the service name), not the host publish. |
| UI `NODE_ENV` | `production` | hardcoded to production for the UI container. keeps the served app in the production build mode the image expects. there is no `.env` knob for this in the current compose. common mistake is adding a `NODE_ENV=development` override "for debugging" and changing asset behavior unexpectedly. operational gotcha: debug with logs and browser tools first; do not casually flip NODE_ENV on a published UI. |

## auth / proxy notes

| name (key) | default value | purpose + notes |
| --- | --- | --- |
| `secrets/htpasswd` | *(from htpasswd.sh)* | nginx htpasswd file consumed by the auth profile. gitignored on purpose — treat it as a secret. generate via `./scripts/htpasswd.sh` rather than hand-editing if you can. common mistake is committing a real htpasswd or leaving world-readable permissions on the secrets dir. operational gotcha: rotating passwords means regenerating this file and recreating the auth container; UI sessions behind basic auth will prompt again. |
| auth nginx upstream | `excalidraw:80` | auth container proxies to the UI service on the compose network by service name. that keeps traffic off the host publish path. it interacts with `EXCALIDRAW_CONTAINER_NAME` / service name consistency in compose. common mistake is pointing upstream at `127.0.0.1:5000` from inside auth, which is the auth container itself or nothing useful. operational gotcha: after renaming the UI service, update the nginx conf upstream in the same change. |
| room basic auth | **do not** | do not put HTTP basic auth in front of the room websocket endpoint. browsers and the collab client do not handle that handshake cleanly. gate the UI with nginx basic auth or an external IdP, and leave the room to network policy / private DNS. common mistake is "securing everything" with the same auth middleware and then collab never connects. operational gotcha: if collab fails right after you "added security," remove auth from the room path first before deeper debugging. |

if you change `VITE_APP_WS_SERVER_URL`, also fix `CORS_ORIGIN` and the reverse-proxy hostnames together.
