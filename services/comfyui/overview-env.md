# comfyui env

ROCm ComfyUI stack. copy `.env.example` → `.env`, copy `compose.yml.template` → `compose.yml`, then `./scripts/up.sh`. stop other GPU workloads first. two processes fighting one AMD GPU is the fastest way to get mysterious HIP failures that look like "bad env" but are just contention.

## .env / compose

| name (key) | default value | purpose + notes |
| --- | --- | --- |
| `COMPOSE_PROJECT_NAME` | `comfyui` | compose project name and the base used for locally tagged artifacts in this stack. keep it stable per host so volumes and container names stay predictable. it interacts with `CONTAINER_NAME` — project rename does not always rename an already-created container. common mistake is changing the project name mid-flight and ending up with orphan containers still holding the GPU. operational gotcha: `down` the old project explicitly before bringing up a renamed one if you changed this. |
| `CONTAINER_NAME` | `comfyui-rocm` | explicit container name. must be unique on the Docker/nerdctl host. scripts and GPU debugging (`exec`, logs) all key off this string. it interacts with whatever else might also want `/dev/kfd` — two named GPU containers can still conflict on the device even with different names. common mistake is cloning the stack for an experiment without renaming and failing create. operational gotcha: after rename, update any systemd units or aliases that still point at `comfyui-rocm`. |
| `RESTART_POLICY` | `unless-stopped` | restart policy for the GPU container after host reboot or crash. `unless-stopped` brings it back automatically, which is what you want for a always-on UI. it interacts with GPU availability at boot — if the AMD modules are not ready yet, you can get restart loops until they are. common mistake is using `always` and masking a bad config that crashloops forever. operational gotcha: if the box dual-boots workloads, stop ComfyUI before starting something else that needs the same GPU; the policy will otherwise fight you. |
| `COMFYUI_IMAGE` | `rocm/comfyui:comfyui-0.18.2.amd0_rocm7.2.0_ubuntu24.04` | full ROCm ComfyUI image tag. pin to a combo that matches your GPU and host ROCm/driver story. it interacts with `HSA_OVERRIDE_GFX_VERSION` and the device mounts — wrong image/ROCm pairing fails at HIP init, not at compose parse time. common mistake is chasing "latest" tags across ROCm minor bumps on a working box. operational gotcha: record the working tag in the host notes; rolling back is faster than rediscovering a compatible matrix. |
| `COMFYUI_BIND` | `127.0.0.1` | host bind address for the published UI port. loopback is correct when a reverse proxy or SSH tunnel is the only entry. it pairs with `COMFYUI_PORT` to form the publish spec. common mistake is binding `0.0.0.0` on a desktop that also sits on a flat LAN with no firewall, exposing a heavy GPU UI. operational gotcha: if you open it wider temporarily for a phone test, put a reminder to close it; this UI is not hardened like a public app. |
| `COMFYUI_PORT` | `8188` | host port mapped to the ComfyUI web UI. change it if 8188 is taken, but update bookmarks and proxies in the same breath. it does not change anything inside the image by itself — only the host publish. common mistake is pointing Caddy at the old port after a conflict-driven change. operational gotcha: smoke-test with a local curl to the bind:port after every recreate before you blame the GPU stack. |
| `COMFYUI_DATA_DIR` | `/opt/comfyui/data` | host directory for models, input, output, and user state in the template layout. this is the expensive durable data — models especially. it should be on a large disk; filling the rootfs with checkpoints is a classic self-own. common mistake is using the older in-tree compose that only mounts models and then losing output/user state on recreate. operational gotcha: prefer the template's full data dir layout; back up what you care about, and never assume outputs live elsewhere. |
| `HIP_VISIBLE_DEVICES` | `0` | which GPU index the process is allowed to see. `0` is the first device ROCm enumerates. it interacts with whatever else is using GPUs on the host and with `HSA_OVERRIDE_GFX_VERSION` when forcing gfx ids. common mistake is leaving `0` after adding a second card and wondering why the "other" GPU never gets load. operational gotcha: confirm indexing with ROCm tools on the host before changing this; wrong index looks like a missing GPU, not a bad number. |
| `HSA_OVERRIDE_GFX_VERSION` | *(empty)* | leave empty unless your AMD gfx IP needs a forced compatibility version for ROCm. when required, it is the difference between init success and failure on some consumer GPUs. it interacts with the image's ROCm build — an override that worked on one tag can break another. common mistake is copying an override from a forum thread for a different card and masking real driver issues. operational gotcha: set only when you have evidence you need it; wrong value yields broken GPU init and wasted debugging on bind mounts. |
| devices | `/dev/kfd`, `/dev/dri` | device nodes bind-mounted into the container for ROCm compute and render. without both, the stack usually cannot talk to the GPU properly. they interact with group membership (`video`, `render`) and host driver state. common mistake is mounting only `/dev/dri` because it "looks like graphics" and skipping `kfd`. operational gotcha: after kernel/driver updates, reconfirm these nodes exist before blaming compose; missing `/dev/kfd` is a host problem. |
| groups | `video`, `render` | supplementary groups so the container user can open the GPU device nodes. required alongside the device mounts. they interact with host udev permissions on `/dev/dri` and `/dev/kfd`. common mistake is dropping groups "for security" and getting permission errors that look like ROCm bugs. operational gotcha: if you run a non-default user in the image, re-verify group needs; copying the template groups blindly onto a custom user can still fail. |
| caps / security | `SYS_PTRACE`, `seccomp:unconfined`, `ipc: host` | template defaults that make this GPU workload actually run under ROCm in practice. they widen the container's privileges relative to a normal app compose. they interact with the device mounts — locking seccomp back down is a common way to break HIP after a "hardening" pass. common mistake is stripping these because a scanner flagged them, then spending hours on opaque GPU init failures. operational gotcha: treat this stack as a trusted GPU worker, not a internet-facing least-privilege service; don't strip casually. |

older in-tree `compose.yml` may only mount models — prefer the template layout for a full data dir.
