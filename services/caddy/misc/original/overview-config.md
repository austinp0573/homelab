# caddy config

compose template under `compose/template/` is the reusable stack. root-level OpenRC / Cloudflare env is a separate older path — prefer the compose tree for new work. examples under `compose/examples/` are Caddyfile patterns, not a second env schema. copy template, then steal Caddyfile snippets from examples rather than forking a whole new compose each time.

## compose `.env` (`compose/template`)

| name (key) | default value | purpose + notes |
| --- | --- | --- |
| `COMPOSE_PROJECT_NAME` | `caddy` | compose project name for the reverse-proxy stack. keep unique if multiple Caddy instances share a docker host. it prefixes networks and default resource names. common mistake is running edge and lab caddy projects with the same name and cross-talking containers. operational gotcha: rename only after `down` if you must; orphan networks are annoying but lost `DATA_DIR` bindings are worse — keep data paths straight. |
| `CONTAINER_NAME` | `caddy` | explicit container name for logs and scripts. stable naming beats compose-generated names when you live in `logs -f`. it collides if two stacks claim `caddy`. common mistake is assuming container name equals hostname in upstream health checks. operational gotcha: smoke scripts that hardcode `caddy` need updates if you rename. |
| `RESTART_POLICY` | `unless-stopped` | brings Caddy back after reboot until you explicitly stop it. correct for an edge/proxy process. it interacts with cert renewals — a permanently stopped container will not renew. common mistake is `no` on an edge host and wondering why sites die after patch reboots. operational gotcha: if you stop Caddy for maintenance, remember you also stopped ACME renewals for that window. |
| `CADDY_IMAGE` | `caddy:alpine` | stock image supports HTTP-01 ACME out of the box. DNS-01 (Cloudflare and friends) needs a custom xcaddy image with the DNS plugin, then point this variable at that image. it interacts with which ports must be reachable and which secrets you mount. common mistake is setting Cloudflare token env while still running stock alpine without the plugin. operational gotcha: pin digests for prod edge; floating `:alpine` on recreate is how surprise Caddy versions show up. |
| `HOST_BIND` | `0.0.0.0` | address for published HTTP/HTTPS ports. `0.0.0.0` is correct for a real edge listener on the host. use `127.0.0.1` when something else terminates TLS in front and Caddy is only local. it pairs with `HTTP_PORT` / `HTTPS_PORT`. common mistake is leaving `0.0.0.0` on a sidecar-only host that should not be publicly reachable. operational gotcha: wrong bind is either "nobody can connect" or "everyone can connect" — check `ss` after changes. |
| `HTTP_PORT` | `80` | host port mapped to container 80. ACME HTTP-01 needs this reachable from the internet when using stock HTTP-01. it interacts with `HOST_BIND` and whatever else wants host :80. common mistake is moving HTTP off 80 for "security" and breaking HTTP-01 challenges. operational gotcha: if another proxy already owns 80/443, do not fight it — change architecture instead of double-binding. |
| `HTTPS_PORT` | `443` | host port mapped to container 443 for TLS. same collision story as HTTP_PORT. browsers expect 443 unless you force ugly URLs. common mistake is publishing HTTPS on a high port but forgetting DNS/clients still hit 443. operational gotcha: after port changes, update firewall allow rules in the same window or you will debug TLS timeouts that are really filtered packets. |
| `DATA_DIR` | `./data` | host directory for certs and ACME account/state. persist across recreates or you re-issue constantly and can hit CA rate limits. it is the most important volume in this stack. common mistake is wiping `./data` to "clear a bad config" and burning Let's Encrypt weekly budgets. operational gotcha: back up this directory with the Caddyfile; restoring sites without ACME state is painful even when keys can reissue. |
| `CONFIG_DIR` | `./config` | caddy config storage directory used by the image for non-Caddyfile state as applicable. keep it persistent next to `DATA_DIR`. it is easy to ignore until you recreate and lose something you cared about. common mistake is git-tracking secrets that landed under config by accident. operational gotcha: treat both data and config as recreate-safe mounts; only the Caddyfile in examples is meant to be casually replaced. |
| `COMPOSE_CMD` | *(optional)* | helper script override for `nerdctl compose` vs `docker compose`. set when the host's default compose invocation is wrong. scripts like `up.sh` / `smoke.sh` honor it when wired. common mistake is fixing your shell alias but leaving scripts calling bare `docker compose`. operational gotcha: set once per host in `.env` so every script path matches the runtime you actually use. |

compose also adds `extra_hosts: host.docker.internal:host-gateway` so `reverse_proxy` can hit services on the host.

## Caddyfile (template placeholders)

| name (key) | default value | purpose + notes |
| --- | --- | --- |
| global `email` | `you@example.com` | ACME account email embedded in the Caddyfile global options. CA accounts and expiry notices tie to this address. change it before first successful issue if you care who gets the mail. common mistake is leaving the example email on a public edge and then not owning the account recovery path. operational gotcha: changing email later is an ACME account identity change — do it deliberately, not casually mid-outage. |
| `admin` | `off` | admin API disabled in the template. turn on only if you need remote config APIs and bind it to a private interface. an open admin API is remote control of your proxy. common mistake is enabling admin on `0.0.0.0` for convenience during debugging. operational gotcha: if you enable it, firewall it like a management plane and turn it back off when done if you do not need it permanently. |
| site address | `example.com` | site block hostname Caddy will serve and obtain certs for. replace with the real FQDN before go-live. it must match public DNS pointing at this host for HTTP-01. common mistake is adding a site block for a name that does not resolve here yet and watching challenges fail. operational gotcha: one hostname change means DNS, Caddyfile, and any upstream `Host` expectations all move together. |
| `reverse_proxy` target | `host.docker.internal:8080` | default upstream pointing at a service on the host via the compose extra_hosts gateway. change per service to the real listen address. for containers on a shared network, prefer service DNS instead of host-gateway. common mistake is proxying to `127.0.0.1:8080` from inside the container and hitting Caddy itself, not the host app. operational gotcha: after upstream moves, reload/restart Caddy and curl the public hostname before blaming the app. |

## example patterns (`compose/examples/`)

not separate env trees — same compose knobs as the template unless noted. steal the Caddyfile idea, keep the template env shape.

| pattern | when / notes |
| --- | --- |
| `edge/` | public listener stack using the same env shape as the template. use when Caddy is the actual internet-facing process on the box. keep `HOST_BIND=0.0.0.0` and persist `DATA_DIR` or you will re-issue certs under traffic. common mistake is copying edge files but leaving example.com site blocks. operational gotcha: edge mistakes are public outages — smoke HTTPS from off-network after every change. |
| `sidecar/` | app-network sidecar pattern where Caddy sits beside an application compose network. may need `APP_NETWORK` (or equivalent) so Caddy can resolve the app service. bind and ports are often narrower than a true edge. common mistake is using host-gateway upstreams in a pure sidecar network where service DNS was the point. operational gotcha: attach networks deliberately; "it works on my edge copy" does not mean the sidecar network attachments match. |
| `http-01/` | stock alpine image plus ports 80/443 reachable for Let's Encrypt HTTP-01. this is the default happy path for public hostnames. it fails closed if something else owns :80 or if DNS points elsewhere. common mistake is testing only locally without an external challenge path. operational gotcha: open 80 end-to-end during issue/renew even if you redirect HTTP later. |
| `dns-01/` | requires a custom `CADDY_IMAGE` built with the DNS provider plugin plus a DNS API token such as `CLOUDFLARE_API_TOKEN=<secret>`. use when HTTP-01 is impossible (wildcards, blocked :80). token scope should be DNS edit only on the zones you need. common mistake is adding the token to stock alpine and wondering why DNS challenges never run. operational gotcha: rotate tokens like secrets and recreate Caddy after image/plugin bumps. |
| `internal-tls/` | internal CA or otherwise non-public TLS for lab/tailnet hostnames. skips public ACME assumptions. clients must trust your internal CA or you will chase browser errors forever. common mistake is mixing public ACME site blocks and internal-only names without clarity. operational gotcha: document which names are public-ACME vs internal so renewals are not attempted against the wrong issuer. |
| `multi-host/` | several site blocks in one Caddyfile. good default for a homelab edge serving many apps. isolate risky experiments so one bad block does not make the file unparsable if you can help it. common mistake is one giant unstructured file with no comments about which upstream owns which host. operational gotcha: `caddy validate` / reload before relying on traffic; a single syntax error drops the whole config. |
| `single-service/` | minimal one-upstream example. best starting point when learning the template. promote to multi-host when you add the second app rather than growing spaghetti early. common mistake is copying single-service repeatedly instead of one Caddy with many blocks. operational gotcha: one Caddy process with many sites usually beats many Caddy containers on small hosts. |
| `websocket/` | long-lived upgrade example. proxy timeouts matter here and also on anything in front of Caddy. idle timeouts that are fine for REST will murder collab/ws apps. common mistake is only fixing app timeouts while HAProxy/nginx in front still cuts at 60s. operational gotcha: test with a real websocket client, not just `curl` to `/`. |
| `basic-auth/` | Caddy-native basic authentication in front of an upstream. fine for low-stakes lab gates; clunky for multi-user SSO needs. credentials handling still matters — do not commit password hashes casually. common mistake is stacking basic auth here and again at the app without realizing users get double prompts. operational gotcha: prefer Tinyauth/forward_auth when you want centralized sessions across apps. |
| `forward-auth-tinyauth/` | `forward_auth` integration with Tinyauth for SSO-ish gating. requires Tinyauth reachable from Caddy and correct redirect URLs. it interacts with cookie domains and which hostnames share auth. common mistake is protecting APIs that need non-browser clients the same way as human UIs. operational gotcha: keep a break-glass path documented for when Tinyauth is down and you locked the proxy. |
| `static-files/` / `spa/` | file_server and SPA fallback patterns. SPA needs the fallback to `index.html` for client routes; static sites usually should not. wrong pattern shows up as refresh 404s on deep links. common mistake is enabling SPA fallback on a directory that should 404 missing files. operational gotcha: mount the content read-only and treat the files path like app data for backups if it is not regenerated from CI. |
| `redirect/` | redirects-only Caddyfile useful for domain migrations and www apex moves. keep it boring — redirects are easy to over-engineer. chain length and absolute vs relative targets matter for SEO and clients. common mistake is redirect loops between apex and www after a DNS change. operational gotcha: test with `curl -I` following nothing first, then with follow, to see the hop chain clearly. |
| `security-headers/` | baseline security headers example to copy from. headers are not a substitute for TLS and auth, but they close easy browser foot-guns. tune CSP carefully or you will break inline-heavy apps. common mistake is pasting a strict CSP from a blog onto an app that needs exceptions. operational gotcha: change headers, hard-refresh, and watch the browser console before calling it done. |

## legacy native / OpenRC-style env (root tree)

only if still using the non-compose path. new work should not expand this — migrate toward `compose/template/` when you touch a host.

| name (key) | default value | purpose + notes |
| --- | --- | --- |
| `CADDY_GLOBAL_EMAIL` | *(set locally)* | ACME email for the native/OpenRC style setup. same role as the Caddyfile `email` in compose land. must be set locally; there is no useful committed default. common mistake is updating compose docs while a host still reads this OpenRC env and wondering why nothing changed. operational gotcha: know which path the host actually runs before editing either tree. |
| `CADDY_GLOBAL_ADMIN_ENDPOINT` | *(set locally)* | admin API bind for the legacy setup. keep it private if enabled at all. same risk profile as compose `admin`. common mistake is exposing it on a public interface because the installer defaulted wide. operational gotcha: if unused, disable/off — fewer open management sockets on the edge box. |
| `CLOUDFLARE_API_TOKEN` | `<secret>` | DNS-01 credential for Cloudflare-integrated native setups. also appears in Alpine `/etc/conf.d/caddy` style wiring. scope the token tightly to DNS. common mistake is a global account token checked into scripts. operational gotcha: rotate and update conf.d / unit env together, then restart Caddy and watch the next renewal. |
| `CADDY_WILDCARD_DOMAIN_0` | *(hostname)* | example indexed env for a wildcard domain such as `*.example.com`. part of the older parameterized config style. indexing means `_0` is only the first entry — more domains need more indices if that scheme is in use. common mistake is setting the wildcard env but still using an image without DNS plugin support. operational gotcha: wildcards imply DNS-01; HTTP-01 will not cover them. |
| `CADDY_NAMED_REQUEST_MATCHER_0` | *(name)* | matcher id in the legacy parameterized setup. ties a named matcher to later hostname/backend parameters. easy to desync if you edit one index and not the others. common mistake is renumbering indices partially after deleting a site. operational gotcha: treat the `_0` `_1` sets as tuples and edit them as a unit. |
| `CADDY_HOSTNAME_PARAMETER_0` | *(host match)* | hostname match parameter paired with matcher/backend index 0. must match DNS and cert coverage. common mistake is a typo'd hostname that only fails when clients hit that name. operational gotcha: after changes, curl each hostname, not just the one you remember. |
| `CADDY_BACKEND_TARGET_0` | *(upstream)* | upstream target for index 0 in the legacy scheme. same host-gateway vs service-DNS caveats as compose reverse_proxy. common mistake is leaving an old IP after the app moved to another host. operational gotcha: pair backend changes with a quick health check against the public hostname. |
