# scanopy config

no `.env.example` — defaults from compose. privileged host-network daemon.

| name (key) | default value | purpose + notes |
| --- | --- | --- |
| project `name` | `scanopy` | Compose project name prefixes containers/networks/volumes. Changing it orphans the old network and volumes unless you migrate carefully. Keep stable on a given host so `nerdctl compose -p scanopy` matches docs. Collision with another stack named `scanopy` will fight for resources. |
| `SCANOPY_LOG_LEVEL` | `info` | Shared verbosity for daemon + server; `debug` is noisy during scans. Too quiet (`warn`/`error`) hides why host discovery failed. Apply via compose env and recreate — editing alone does nothing until restart. Use debug briefly, then drop back to info so disks/logs stay sane. |
| `SCANOPY_SERVER_URL` | `http://127.0.0.1:60072` | Daemon (host net) calls the server API here. `127.0.0.1` works because the daemon shares the host network namespace. Pointing at the wrong port/IP means scans never report results while the UI still loads. Keep HTTP unless you terminate TLS in front and rewrite this URL. |
| `POSTGRES_DB` | `scanopy` | Hardcoded DB name in compose; app DSN must use the same name. Renaming requires a fresh volume or a dump/restore — do not half-change it. Appears in `SCANOPY_DATABASE_URL` path segment. Treat as immutable after first successful start. |
| `POSTGRES_USER` | `postgres` | Superuser-style default from the example stack — fine for lab, not ideal for shared Postgres. Must match the user embedded in `SCANOPY_DATABASE_URL`. Changing user without recreating the volume leaves auth failures. Prefer a dedicated role if you ever expose this DB beyond the compose net. |
| `POSTGRES_PASSWORD` | `<secret>` | Example compose often ships `password` — **change before any LAN exposure**. Password is inlined into `SCANOPY_DATABASE_URL`; mismatch = server cannot talk to Postgres. Rotating means updating both the Postgres env and the app DSN, then recreating. Never commit the real value. |
| `SCANOPY_DATABASE_URL` | `postgresql://postgres:…@postgres:5432/scanopy` | Full DSN the server uses; host `postgres` is the compose service DNS name. Wrong password/db name here is the #1 boot failure. Daemon does not use this URL — only the server. Keep credentials in sync with `POSTGRES_*` or you get cryptic connection refused/auth errors. |
| `SCANOPY_WEB_EXTERNAL_PATH` | `/app/static` | Hardcoded static asset root inside the server image. Do not remap unless you know the image layout changed. Broken path = blank UI with API still answering. Leave alone unless upstream docs say otherwise. |
| `SCANOPY_PUBLIC_URL` | `http://localhost:60072` | URL the UI/server assumes clients use for links and redirects. Set to the reverse-proxy HTTPS name in real deploys or cookies/links go to localhost. Mismatch causes “works on the host, broken remotely” symptoms. Update whenever DNS or TLS fronting changes. |
| `SCANOPY_INTEGRATED_DAEMON_URL` | `http://host.docker.internal:60073` | Server → host-network daemon callback. `host.docker.internal` must resolve (nerdctl/docker extra_hosts often required on Linux). Wrong URL = UI up, scans stuck/pending. Port `60073` is the daemon side — do not confuse with server `60072`. |
| server publish | `60072:60072` | Host port for the web/API; proxy this, not the daemon port. Binding `0.0.0.0` exposes an unauthenticated lab scanner UI unless gated. Changing host port requires updating `SCANOPY_PUBLIC_URL` and any HAProxy snippets. Keep daemon unpublished — it is host-net already. |
| daemon | `network_mode: host`, `privileged: true` | Required for raw scanning; host net + privileged is a large trust boundary. Do not drop privileges “to harden” without accepting broken scans. Conflicts with other host-net listeners on the same ports. Isolate this host if you care about blast radius. |
| network subnet | `172.31.0.0/16` | Fixed IPAM for the compose bridge between server and Postgres. Collision with an existing `172.31.0.0/16` on the host breaks create. Changing subnet after first up may orphan containers until recreate. Daemon is host-net and does not sit on this bridge. |
