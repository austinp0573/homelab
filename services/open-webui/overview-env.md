# open-webui env

copy `compose.yml.template` → `compose.yml`. needs `llm-backend` + llama-cpp + rag-headless up first. deploy often `/opt/llm-open-webui`.

| name (key) | default value | purpose + notes |
| --- | --- | --- |
| `COMPOSE_PROJECT_NAME` | `open-webui` | Compose project for the WebUI container and its named data volume. Keep stable or you orphan `open_webui_data` under another project name. Distinct from `llm-rag-ui` on purpose — do not run both as primary RAG UIs without a reason. Scripts and deploy paths often assume this string. |
| `CONTAINER_NAME` | `open-webui` | Container/DNS name on `llm-backend`. Peers rarely call it; humans and proxies do. Renaming breaks muscle memory and any HAProxy backend samples keyed on this name. One WebUI container owning the volume is the model — not a swarm of replicas. |
| `RESTART_POLICY` | `unless-stopped` | Keeps the UI up across reboots. UI up while llama is down just means chat errors — still fine. Stop when doing invasive volume work. Not a GPU process; restart policy does not steal the accelerator. |
| `OPEN_WEBUI_IMAGE` | `ghcr.io/open-webui/open-webui:v0.10.2` | Pinned Open WebUI release. Migrations on upgrade can touch the sqlite/volume — snapshot first. Floating tags have burned me on RAG setting renames. Match docs to this version when chasing feature flags. |
| `LLM_NETWORK` | `llm-backend` | External network shared with llama-cpp, qdrant, and embed. Without it, `OPENWEBUI_API_BASE_URL` DNS fails and people "fix" it with host IPs. Create the network before up. Do not attach only to bridge and expect service names to resolve. |
| `WEBUI_BIND` | `127.0.0.1` | Host publish bind for the UI. Loopback + HAProxy/Tinyauth is the intended edge path. Binding `0.0.0.0` with `ENABLE_SIGNUP=True` is how you get surprise accounts. Keep publish tight even though app auth exists. |
| `WEBUI_PORT` | `3000` | Host port → container `:8080`. Browser and reverse proxies use 3000 on the host side. Collision with Grafana's common 3000 is a classic lab footgun — move one of them. Inside the network, other containers still hit WebUI's 8080 if they ever need to. |
| `OPENWEBUI_API_BASE_URL` | `http://llama-cpp:8080/v1` | Mapped into `OPENAI_API_BASE_URLS` for chat. Must be the llama container DNS on `llm-backend`, including `/v1`. Pointing at host `127.0.0.1:8080` from inside the container talks to the container itself, not the host — classic Docker mistake. llama must be running first. |
| `OPENWEBUI_API_KEY` | `local` | Mapped to `OPENAI_API_KEYS`; dummy for llama.cpp. Non-empty keeps the OpenAI client path happy. A real secret here does not protect llama. If you add multiple base URLs later, key list length must match. |
| `WEBUI_AUTH` | `True` | Enables WebUI's built-in authentication. `False` is only for break-glass local experiments. Combined with signup flags this is your account gate before Tinyauth/HAProxy. Turning auth off on a published bind is negligence. |
| `ENABLE_SIGNUP` | `True` | Allows creating the first admin on a fresh volume. Set `False` after that admin exists or anyone who can reach the UI can register. Fresh volume + True + open bind is the usual incident. I flip it false immediately after bootstrap. |
| `WEBUI_SECRET_KEY` | `<secret>` | Session/crypto secret for the app. Generate with `openssl rand -hex 32` and never commit. Changing it invalidates sessions. Shared across replicas if you ever had them — here you do not, but still treat as production secret material. |
| `QDRANT_URI` | `http://llm-qdrant:6333` | Vector DB endpoint for WebUI RAG. Requires rag-headless Qdrant on the same network. Wrong name or down Qdrant breaks document indexing while chat may still work. Do not point this at a Qdrant you also smash with `ingest.sh` into WebUI-owned collections. |
| `RAG_OPENAI_API_BASE_URL` | `http://llm-embed:8080/v1` | Embeddings OpenAI-compat base URL (rag-headless embed container). Note container port 8080, not host 8081. Chat llama URL and embed URL are different services — mixing them embeds with a chat model and fills Qdrant with junk. Embed is CPU; leave it up with WebUI. |
| `RAG_OPENAI_API_KEY` | `local` | Dummy key for the embed client path. Same semantics as the chat key against llama.cpp. Keep non-empty. No security boundary here without a real gateway. |
| `RAG_EMBEDDING_MODEL` | `nomic-embed-text-v1.5.Q8_0.gguf` | Model name WebUI sends to the embed server; must match `EMBED_MODEL_FILE` in rag-headless. Mismatch yields embed errors or wrong dimensionality vs existing collections. Changing models means new collections / reindex, not a casual toggle. After a model swap, wipe or rename affected Qdrant collections rather than hoping old vectors still retrieve well. |
| `RAG_EMBEDDING_BATCH_SIZE` | `8` | How many chunks per embed batch. Higher is faster until the CPU embed server tips over; lower is gentler under load. Tune when ingesting large libraries. Does not change vector size — only throughput/latency. |
| `ENABLE_OLLAMA_API` | `False` | Hardcoded off in this template — we speak OpenAI-compat to llama.cpp, not Ollama. Turning on without an Ollama daemon adds noisy failed probes. Leave false unless you deliberately add Ollama to the network. If you truly add Ollama later, wire it on `llm-backend` and flip this with a matching base URL, not by hope. |
| `VECTOR_DB` | `qdrant` | Hardcoded vector backend selection for WebUI. Other values expect different env and storage. Changing without migrating data orphans documents in the UI. Pair with a live `QDRANT_URI`. |
| `RAG_EMBEDDING_ENGINE` | `openai` | Hardcoded to use the OpenAI-compatible embed HTTP API (our llama.cpp embed server). Other engines want local models inside WebUI or different providers. Do not flip to `ollama` thinking it will hit llama-cpp. Keep this on `openai` for the headless embed container; local-in-WebUI embedding fights the shared Qdrant design. |
| `ENABLE_ASYNC_EMBEDDING` | `False` | Hardcoded sync embedding behavior for this lab pin. Async can race or obscure failures depending on WebUI version. Leave until you have a reason and a tested upgrade path. If ingest seems "stuck", check embed server logs before blaming this flag. |
| volume | `open_webui_data` | Named volume for app DB, uploads, and WebUI-managed RAG state. Back this up if the chats/docs matter. Deleting the volume resets admin/signup to first-boot behavior. Not a substitute for Qdrant's own data dir — both matter. |
